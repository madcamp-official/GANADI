## 🟢 오전 — 인식률을 대전에 쓸 수준으로

### Step 1. 호랑이·양 자세 실험 (30분, 제일 싼 해결책부터)

원인은 확정돼 있다: 두 손이 겹쳐 MediaPipe가 **한 손만** 잡고, 그러면 특징 90 중 45가 0으로 채워져 **정보 자체가 사라진다.** 모델을 바꿔도 없는 정보는 못 만든다.

- [ ] `npm run dev:client` → http://localhost:5173/recognizer-test.html
- [ ] 호랑이·양을 맺으면서 **손 뼈대가 몇 개 그려지는지** 확인
- [ ] **손을 2~3cm 벌려** 인장 모양은 유지한 채 두 손이 안정적으로 잡히는 자세를 찾는다
- [ ] 찾으면 **그 자세를 실전 자세로 확정**하고 3차 수집 때 그 자세로 찍는다

> **왜 이걸 먼저 하나**: 되면 모델을 안 건드리고 끝난다. 안 되더라도 30분이면 판별되고, 그 결과가 Day 4 모델 작업의 입력이 된다.

### Step 2. 3차 수집 — **제3자 1명 필수** (20~30분)

기획안 §4.3이 명시한 항목이고, **오늘이 마지막 기회**다(Day 4는 학습, Day 5는 배포).

- [ ] `npm run collect` → 12종 × 30장
- [ ] **제3자 1명 이상**을 붙잡아 최소 5분. 지금 데이터는 전부 팀원 손이라 **시연 때 심사위원 손에서 무너진다**
- [ ] 조명·시간대·카메라 각도를 1·2차와 또 다르게
- [ ] **호랑이·양은 Step 1에서 찾은 자세로**
- [ ] `✗ 인장 아님` 30장도 (오탐률 측정용)
- [ ] `data/seals_2026-07-28_*` 별도 폴더

### Step 3. 재생성 + 검증 (10분)

```bash
node tools/makeCentroids.mjs          # 1·2·3차 전부로 재생성
node tools/replay.mjs                 # 성적·오탐률
```

- [ ] **교차 세션 성적이 올랐는지**가 핵심 — 2차 반영 시점의 기록: 1차→2차 33.8%, 합본 96.0%
- [ ] 오탐률이 0%를 유지하는 선에서 `ACCEPT_THRESHOLD` 재확인 (현재 4.0 / `MARGIN` 0.5)
- [ ] 제3자 손이 잘 잡히는지 인장별로 확인 — **여기서 떨어지는 인장이 진짜 위험한 인장이다**

## 🟡 오후 — PC 2대 실대전 (오늘의 본체)

### Step 5. 두 PC를 같은 서버에 붙이기

`getUserMedia`는 **HTTPS 또는 localhost**에서만 된다. 다른 PC에서 열면 `http://192.168.x.x:5173`이라 **웹캠이 안 잡힌다.** 여기서 막히면 실대전 자체가 불가능하니 오후 시작하자마자 확인한다.

- [ ] 경로 결정 (B와): **터널 도메인**(vite.config에 `.madcamp-kaist.org` 이미 허용됨) / vite `https: true` + 자체 인증서 / 임시 배포
- [ ] 두 PC 모두에서 **웹캠 권한이 잡히는지** 먼저 확인 (HandCheck 통과 여부로 판정)
- [ ] 클라가 바라보는 서버 주소 확인 — `VITE_SERVER_URL` (기본 `http://localhost:3001`). **상대 PC에서는 localhost가 자기 자신이라 안 된다**
- [ ] 서버 CORS는 현재 `origin: '*'`라 막히지 않음 (배포 시 조이는 건 Day 5)

### Step 6. 실대전 완주 (DoD ①)

- [ ] 방 만들기 → 코드 공유 → 입장 → 매칭
- [ ] **양쪽 모두 손으로** 시퀀스 진행 (스페이스바 금지)
- [ ] 체력 0까지 완주 → 결과 화면
- [ ] 상대 진행 바가 실시간으로 움직이는지

### Step 7. 예외 상황 확인 (공동)

- [ ] **동시 완성 타이브레이크** — 서버 수신 순서로 판정된다([referee.js](../server/src/referee.js) `roundResolved` 플래그). 양쪽이 거의 동시에 완성해도 **한쪽만** 이기는지, 양쪽 화면의 승패가 일치하는지
- [ ] **이탈 몰수승** — 한쪽이 탭을 닫으면 남은 쪽이 `MATCH_OVER (reason: forfeit)`로 이기는지
- [ ] **재접속 복구는 스코프 아웃** (기획안 §6). 안 된다고 붙잡지 말 것
- [ ] 인식이 양쪽에서 동시에 도는데 **렉이 걸리지 않는지** — 걸리면 Step 8

### Step 8. fps 스로틀 (Day 2 잔여, 렉이 있으면 승격)

- [ ] [handTracker](../client/src/recognition/handTracker.js)에 마지막 추론 시각을 두고 `now - lastInfer < 1000/18`이면 건너뛰기
- [ ] 스로틀 후 **`VOTE_WINDOW`(8) 재확인** — 프레임이 줄면 8프레임 다수결이 실시간으로 길어진다. 18fps면 8프레임 ≈ 0.44초라 홀드(0.4초)와 겹쳐 굼떠진다 → 5~6이 맞을 수 있다
- [ ] 스로틀 전/후 체감 반응속도 비교
